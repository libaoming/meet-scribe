# PRD — meet-scribe

> 状态：v1 已拍板（2026-07-13，来自与用户的设计对话与 AskUserQuestion 拍板）。变更须回填本文件。

## 背景与动机
### 问题陈述（用户视角）
用户（AI PM）线下会议频繁：手记纪要分心、漏结论漏待办；录音容易，但「录完→转写→整理→归档」每步都是手动摩擦，导致录了也不整理；且不想为 SaaS 转写额度付费。

### 方案概述（用户视角）
录音文件一落盘（`~/Meetings/inbox/`），本机自动完成 转写（含说话人分离）→ 结构化纪要 → 落 Obsidian vault → 系统通知。全链路免费、离线、无人值守。

## 目标用户
用户本人（单用户工具），Apple Silicon Mac + iPhone。

## User Stories
1. 作为参会者，我想要一条命令（`meet start/stop`）或手机录音就能开始/结束录制，以便开会时不被工具分心。
2. 作为参会者，我想要录音结束后无人工干预地得到中文转写稿，以便不再手动整理录音。
3. 作为参会者，我想要转写稿区分说话人（说话人1/2/…），以便追溯「谁说的、谁承诺的」。
4. 作为参会者，我想要自动生成结构化纪要（主题/结论/待办·责任人/分歧/下一步），以便直接可用可转发。
5. 作为知识库用户，我想要纪要自动落 `~/ObsidianVault/meetings/`，以便 recall 能检索历史会议承诺。
6. 作为 iPhone 用户，我想要手机录音「存储到文件」后自动进入管线，以便线下会用收音更好的手机当主力录音设备。
7. 作为用户，我想要管线完成时收到系统通知并自动打开纪要，以便第一时间校对说话人真名。

## 技术约束
- 全链路 $0 边际成本：本地 WhisperX + pyannote + claude -p（订阅内）。
- 国内网络：HF 模型下载统一走 `HF_ENDPOINT=https://hf-mirror.com`。
- pyannote 模型 gated：需用户 HF 账号接受许可 + token（S3 唯一外部阻塞）。
- 无守护常驻大进程：launchd 事件触发，跑完即退。

## 测试策略 / 验证接缝
**接缝只有 1 个：`pipeline.sh <音频文件>`**（launchd 也只是调它）。所有 feature 的 verify 都打这条命令或其子步骤：
- fixture 先行：`fixtures/meeting-2spk.wav`（macOS `say` 双音色合成的中文双人对话，内容含约定关键词与明确待办），不依赖真实录音即可全链路回归。
- 录音层单独接缝：`meet start/stop`，verify 用文件存在 + `ffprobe` 时长。
- 判定一律「命令吐可判定信号」：grep 关键词 / test -f / ffprobe 数值比较，不靠人读。

## 验收标准（E2E，可机跑）
`cp fixtures/meeting-2spk.wav ~/Meetings/inbox/` 后无人工干预：
1. `~/ObsidianVault/meetings/` 出现当日 md（`test -f`）；
2. 纪要含五段标题（grep 待办/结论）且含说话人标签（grep 说话人）；
3. 原音频出现在 `~/Meetings/archive/`（`test -f`）；
4. 期间弹出 macOS 通知（人工观察一次即可，不入自动回归）。

## Out of Scope（范围外）
实时转写；线上会议系统音频捕捉（BlackHole 等）；日历自动开录；声纹自动认人；多语言优化（中文为主）；任何云端 ASR；移动端 App。

## 里程碑
- M1（本期全部）：S1 录音入口 → S2 转写 → S3 说话人分离 → S4 纪要落 vault → S5 launchd 自动化 → S6 iPhone 入口。

## 补充说明（已知的未知）
- 单麦克风多人重叠说话时 pyannote 准确率有限（≥5 人或大会议室退化）；物理缓解=录音设备放桌子中央。
- 长会议（>2h）转写耗时/内存待实测，先按 1h 校准。
